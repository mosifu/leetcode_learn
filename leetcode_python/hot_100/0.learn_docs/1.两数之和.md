# 一、Python 语法知识

## 1.1 `enumerate()`：同时获取索引和值

`enumerate()` 是 Python 的内置函数，作用是在遍历一个可迭代对象时，同时获得当前元素的计数值和元素本身。

基本语法：

```python
enumerate(iterable, start=0)
```

其中：

- `iterable`：可迭代对象，例如列表、元组、字符串。
- `start`：计数的起始值，默认为 `0`。

例如：

```python
nums = [2, 7, 11, 15]

for i, item in enumerate(nums):
    print(i, item)
```

输出：

```text
0 2
1 7
2 11
3 15
```

索引和值的对应关系：

| 索引 `i` | 元素 `item` |
|---:|---:|
| 0 | 2 |
| 1 | 7 |
| 2 | 11 |
| 3 | 15 |

### 与 `range(len(nums))` 的区别

写法一：通过索引访问元素。

```python
for i in range(len(nums)):
    item = nums[i]
```

写法二：通过 `enumerate()` 同时获取索引和值。

```python
for i, item in enumerate(nums):
    ...
```

两种写法都正确。如果需要同时使用索引和值，通常优先使用 `enumerate()`，代码更加简洁、直观。

如果只需要元素值，则可以直接写：

```python
for item in nums:
    ...
```

### `enumerate()` 的 `start` 参数

默认从 `0` 开始，也可以指定其他起始值。

```python
letters = ["a", "b", "c"]

for i, letter in enumerate(letters, start=1):
    print(i, letter)
```

输出：

```text
1 a
2 b
3 c
```

**注意：** `start=1` 只改变 `enumerate()` 产生的计数值，并不会改变列表自身的索引。

LeetCode 题目通常要求返回列表的实际索引，因此一般使用默认的 `start=0`。

### `enumerate()` 返回什么？

`enumerate()` 返回一个 `enumerate` 对象，它是一个迭代器，而不是列表。

```python
nums = ["a", "b", "c"]

result = enumerate(nums)

print(list(result))
# [(0, 'a'), (1, 'b'), (2, 'c')]
```

这里使用 `list()`，是为了将迭代产生的结果全部收集到列表中，方便观察。

日常遍历时，通常不需要进行转换：

```python
for i, item in enumerate(nums):
    ...
```

## 1.2 序列解包

在下面的代码中：

```python
i, item = (0, 2)
```

Python 会将元组中的两个值分别赋给两个变量：

```python
i = 0
item = 2
```

这称为序列解包（sequence unpacking）。

因此：

```python
for i, item in enumerate(nums):
    ...
```

可以理解为：

1. `enumerate(nums)` 每次产生一个二元组，例如 `(0, 2)`。
2. Python 自动将这个二元组拆开。
3. 第一个值赋给 `i`，第二个值赋给 `item`。

这也是 Python 中非常常见的简洁语法。

## 1.3 Python 字典 `dict`

字典是一种保存键值映射的数据结构。

例如：

```python
cache = {
    2: 0,
    7: 1,
    11: 2
}
```

含义是：

- 键 `2` 对应值 `0`。
- 键 `7` 对应值 `1`。
- 键 `11` 对应值 `2`。

在两数之和问题中，我们使用：

```python
cache[item] = i
```

表示：

**把当前数字 `item` 作为键，把它的索引 `i` 作为值。**

常见的字典操作：

```python
cache = {}

# 添加键值对
cache[7] = 1

# 读取键对应的值
print(cache[7])  # 1

# 判断某个键是否存在
print(7 in cache)  # True
```

如果访问一个不存在的键：

```python
cache = {}

# cache[100]
```

会抛出 `KeyError` 异常。

如果不确定某个键是否存在，可以先检查：

```python
if 100 in cache:
    value = cache[100]
```

## 1.4 `other in cache` 和 `other in cache.keys()`

这两种写法都可以判断一个键是否存在：

```python
other in cache
```

```python
other in cache.keys()
```

**推荐写法：**

```python
if other in cache:
    ...
```

原因：

1. Python 字典本身就支持使用 `in` 检查键是否存在。
2. 不需要显式调用 `.keys()`。
3. 代码更加简洁、易读。
4. 对普通 Python 字典而言，两种写法的平均查找时间复杂度都是 `O(1)`。

需要特别注意：

**`in dict` 默认检查的是键，而不是值。**

例如：

```python
cache = {
    2: 0,
    7: 1,
    11: 2
}

print(7 in cache)           # True
print(1 in cache)           # False
print(1 in cache.values())  # True
```

解释：

- `7 in cache`：检查键 `7` 是否存在。
- `1 in cache`：检查键 `1` 是否存在。
- `1 in cache.values()`：检查值 `1` 是否存在。

## 1.5 字典的 `keys()`、`values()` 和 `items()`

```python
cache = {
    2: 0,
    7: 1
}

print(cache.keys())    # 所有键
print(cache.values())  # 所有值
print(cache.items())   # 所有键值对
```

也可以遍历字典中的键值对：

```python
for key, value in cache.items():
    print(key, value)
```

注意区分：

| 表达式 | 含义 |
|---|---|
| `cache` | 字典对象 |
| `cache.keys()` | 字典的键视图 |
| `cache.values()` | 字典的值视图 |
| `cache.items()` | 字典的键值对视图 |
| `cache[key]` | 读取指定键对应的值 |

这些视图是动态的，会反映字典后续的变化，并不是普通列表的副本。

## 1.6 字典中重复键的处理

字典的键具有唯一性。

```python
cache = {}

cache[3] = 0
cache[3] = 2

print(cache)
# {3: 2}
```

第二次执行 `cache[3] = 2` 时，会覆盖原来键 `3` 对应的值 `0`。

这在两数之和的第二种解法中非常重要，因为：

```python
cache[item] = i
```

如果同一个数字出现多次，字典只会保留该键最后一次赋值对应的索引。

# 二、哈希表的概念与原理

## 2.1 什么是哈希表？

哈希表（Hash Table）是一种利用键快速查找数据的数据结构。

Python 中常用的：

- `dict`：字典。
- `set`：集合。

都基于哈希机制实现。

哈希表的典型用途包括：

- 根据键查找值。
- 判断某个元素是否存在。
- 记录元素出现的位置。
- 统计元素出现次数。
- 去重。
- 建立两个数据之间的映射关系。

例如：

```python
cache = {
    2: 0,
    7: 1,
    11: 2
}
```

如果需要查找数字 `7` 对应的索引：

```python
print(cache[7])  # 1
```

通常不需要像遍历列表那样从头逐个检查元素。

## 2.2 哈希表的基本原理

可以将哈希表的工作过程简化理解为：

```text
输入一个键 key
      |
      v
   哈希函数
      |
      v
计算哈希值，帮助定位存储位置
      |
      v
找到对应的数据
```

哈希函数会根据键计算哈希值，哈希表利用这个结果帮助定位数据。

需要注意，这只是帮助理解的简化模型。实际哈希表还涉及哈希冲突处理、存储布局和内部查找机制。

### 什么是哈希冲突？

不同的键可能产生相同的哈希值，或者映射到同一个存储位置，这种情况称为哈希冲突。

哈希表必须处理冲突，因此不能保证所有情况下的查找都严格为常数时间。

对于 Python 字典，常见操作的平均时间复杂度通常是 `O(1)`，但特殊情况下可能退化。

另外，字典的键必须是可哈希的。整数、字符串等常见类型通常可以作为键；列表和字典本身不可哈希，不能直接作为字典键。

## 2.3 哈希表为什么能优化两数之和？

两数之和的数学关系为：

\[
a+b=target
\]

移项后：

\[
b=target-a
\]

当我们遍历到当前数字 `item` 时，可以直接计算另一个数字：

```python
other = target - item
```

接着检查：

```python
if other in cache:
    ...
```

如果 `other` 已经存在于字典中，就意味着之前遍历过的某个数字可以与当前数字组成目标值。

因此，不需要再遍历所有剩余元素寻找补数。

**核心思想：将反复搜索一个数字的问题，转化为哈希表的键查找。**

## 2.4 什么时候应该考虑使用哈希表？

遇到以下问题时，可以考虑 `dict` 或 `set`：

| 问题特征 | 常见方案 |
|---|---|
| 判断某个数字是否出现过 | `set` |
| 记录数字及其索引 | `dict` |
| 统计元素出现次数 | `dict` 或 `Counter` |
| 查找满足特定关系的补数 | `dict` |
| 按某种特征进行分组 | `dict` |
| 去除重复元素 | `set` |

LeetCode 中常见的相关题型：

- 两数之和。
- 存在重复元素。
- 字母异位词分组。
- 最长连续序列。
- 字符频率统计。

# 三、两数之和的三种解法

## 3.1 题目思路

给定一个整数数组 `nums` 和一个目标值 `target`，寻找两个不同元素，使它们的和等于目标值，并返回这两个元素的索引。

例如：

```python
nums = [2, 7, 11, 15]
target = 9
```

因为：

\[
2+7=9
\]

所以答案是：

```python
[0, 1]
```

接下来分析三种解法。

## 3.2 Solution1：暴力枚举

```python
class Solution1:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        for i, item in enumerate(nums):
            for j in range(i + 1, len(nums)):
                post = nums[j]

                if item + post == target:
                    return [i, j]

        return []
```

### 思路

1. 外层循环选择第一个数字。
2. 内层循环遍历它后面的数字。
3. 判断两个数字的和是否等于 `target`。
4. 找到答案就返回索引。
5. 如果遍历结束仍然没有答案，就返回空列表。

为什么内层循环从 `i + 1` 开始？

```python
for j in range(i + 1, len(nums)):
```

因为这样可以：

- 避免一个元素与自己配对。
- 避免重复检查相同的元素对。

例如，检查过索引 `(0, 1)` 后，就不必再检查 `(1, 0)`。

### 时间复杂度

最坏情况下，需要检查所有不同索引的元素对。

检查次数为：

\[
\frac{n(n-1)}{2}
\]

忽略常数和低阶项，得到：

\[
\boxed{O(n^2)}
\]

### 空间复杂度

只使用了固定数量的变量：

- `i`
- `item`
- `j`
- `post`

变量数量不会随着输入规模增长，因此额外空间复杂度为：

\[
\boxed{O(1)}
\]

## 3.3 Solution2：先建表，再查找

```python
class Solution2:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        cache = {}

        # 第一遍：建立数字到索引的映射
        for i, item in enumerate(nums):
            cache[item] = i

        # 第二遍：查找补数
        for i, item in enumerate(nums):
            other = target - item

            if other in cache and i != cache[other]:
                return [i, cache[other]]

        return []
```

### 思路

第一遍遍历：

```python
cache[item] = i
```

把所有数字及其索引存入字典。

第二遍遍历：

```python
other = target - item
```

计算当前数字所需要的补数。

接着：

```python
if other in cache and i != cache[other]:
```

检查补数是否存在，并且确保两个索引不同。

### 为什么需要 `i != cache[other]`？

因为在第二次遍历之前，字典已经保存了整个数组中的数字。

例如：

```python
nums = [3, 2, 4]
target = 6
```

建表后：

```python
cache = {
    3: 0,
    2: 1,
    4: 2
}
```

遍历到第一个数字 `3` 时：

```python
other = 6 - 3  # 3
```

虽然 `3 in cache` 为 `True`，但它对应的索引是 `0`，恰好与当前索引相同。

因此，需要通过：

```python
i != cache[other]
```

避免把同一个元素使用两次。

### 时间复杂度

第一遍遍历为 `O(n)`。

第二遍遍历也是 `O(n)`，并且每轮的字典查找平均为 `O(1)`。

因此：

\[
O(n)+O(n)=O(2n)=O(n)
\]

平均时间复杂度：

\[
\boxed{O(n)}
\]

### 空间复杂度

字典最坏情况下可能保存与输入规模成正比数量的元素。

因此：

\[
\boxed{O(n)}
\]

## 3.4 Solution3：单次遍历哈希表

```python
class Solution3:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        cache = {}

        for i, item in enumerate(nums):
            other = target - item

            if other in cache:
                return [i, cache[other]]

            cache[item] = i

        return []
```

这是两数之和中非常经典的哈希表解法。

### 核心思想：先查找，再存入

每次循环执行以下步骤：

1. 读取当前数字 `item`。
2. 计算补数 `other`。
3. 检查补数是否在字典中。
4. 如果存在，返回两个索引。
5. 如果不存在，把当前数字及其索引存入字典。

关键代码：

```python
other = target - item

if other in cache:
    return [i, cache[other]]

cache[item] = i
```

### 执行过程示例

输入：

```python
nums = [2, 7, 11, 15]
target = 9
```

| 当前索引 | 当前数字 | 补数 | 查找前的字典 | 执行结果 |
|---:|---:|---:|---|---|
| 0 | 2 | 7 | `{}` | 没找到 7，保存 `{2: 0}` |
| 1 | 7 | 2 | `{2: 0}` | 找到 2，返回 `[1, 0]` |

返回 `[1, 0]` 与 `[0, 1]` 表示同一对索引。如果题目没有规定返回顺序，两种结果都有效。

### 为什么不需要 `i != cache[other]`？

因为当前数字还没有被存入字典。

查找时：

```python
if other in cache:
```

字典只包含之前遍历过的数字，不包含当前数字刚刚对应的索引。

例如：

```python
nums = [3, 2, 4]
target = 6
```

第一次遍历到 `3` 时：

```python
other = 6 - 3  # 3
```

此时 `cache` 为空，因此不会将数字 `3` 与自身配对。

然后才执行：

```python
cache[3] = 0
```

因此，**先查找再存入**就能避免当前元素与自身配对的问题。

### 时间复杂度

循环最多执行 `n` 次。

每次循环进行常数次运算，以及常数次平均 `O(1)` 的字典操作。

因此平均时间复杂度为：

\[
\boxed{O(n)}
\]

严格来说，Python 字典操作的 `O(1)` 是平均复杂度；遇到特殊哈希冲突情况时，单次操作可能退化。LeetCode 通常按平均情况分析该算法。

### 空间复杂度

字典最多可能保存与输入规模成正比数量的元素。

因此：

\[
\boxed{O(n)}
\]

# 四、时间复杂度怎么判断

## 4.1 什么是时间复杂度？

时间复杂度描述的是：当输入规模 `n` 增大时，算法执行工作量的增长趋势。

它不直接表示实际运行了多少秒，而是用于比较算法在输入规模扩大时的效率。

## 4.2 常见时间复杂度

| 复杂度 | 名称 | 常见示例 |
|---|---|---|
| `O(1)` | 常数级 | 访问列表中的一个索引 |
| `O(log n)` | 对数级 | 有序数组的二分查找 |
| `O(n)` | 线性级 | 遍历长度为 `n` 的列表 |
| `O(n log n)` | 线性对数级 | 常见高效排序算法 |
| `O(n²)` | 平方级 | 两层随 `n` 增长的嵌套循环 |
| `O(2ⁿ)` | 指数级 | 某些枚举所有子集的算法 |
| `O(n!)` | 阶乘级 | 某些枚举所有排列的算法 |

## 4.3 单层循环

```python
for i in range(n):
    print(i)
```

循环执行约 `n` 次，每次操作为常数级别。

因此：

\[
T(n)=n \times O(1)=O(n)
\]

## 4.4 两层嵌套循环

```python
for i in range(n):
    for j in range(n):
        print(i, j)
```

外层执行 `n` 次，内层每次执行 `n` 次。

总执行次数：

\[
n \times n=n^2
\]

因此时间复杂度为：

\[
\boxed{O(n^2)}
\]

## 4.5 内层循环从 `i + 1` 开始

```python
for i in range(n):
    for j in range(i + 1, n):
        ...
```

执行次数为：

\[
(n-1)+(n-2)+\cdots+1
\]

求和得到：

\[
\frac{n(n-1)}{2}
\]

展开：

\[
\frac{n^2-n}{2}
\]

忽略常数因子和低阶项后：

\[
\boxed{O(n^2)}
\]

因此，即使内层循环从 `i + 1` 开始，整体仍然是平方级时间复杂度。

## 4.6 两个连续循环

```python
for x in nums:
    ...

for x in nums:
    ...
```

第一个循环是 `O(n)`，第二个循环也是 `O(n)`。

总复杂度：

\[
O(n)+O(n)=O(2n)=O(n)
\]

**两个连续的线性循环通常仍然是 `O(n)`；两个嵌套的线性循环通常是 `O(n²)`。**

## 4.7 哈希表操作的复杂度

在普通 Python 字典中：

| 操作 | 平均时间复杂度 |
|---|---|
| `key in cache` | `O(1)` |
| `cache[key]` | `O(1)` |
| `cache[key] = value` | `O(1)` |
| `cache.get(key)` | `O(1)` |

这些都是平均情况。特殊哈希冲突等情况下，操作可能退化。

因此，在两数之和的单次遍历解法中：

```python
for i, item in enumerate(nums):
    other = target - item

    if other in cache:
        return [i, cache[other]]

    cache[item] = i
```

每轮的平均工作量为常数级别，最多遍历 `n` 个元素，所以平均时间复杂度是 `O(n)`。

## 4.8 最好、平均和最坏情况

- **最好情况：** 输入使算法很快结束时的工作量。
- **平均情况：** 根据特定输入分布或分析假设衡量的平均工作量。
- **最坏情况：** 算法可能遇到的最大工作量。

例如，单次遍历哈希表解法可能很早找到答案，但也可能遍历完整个列表。

算法分析通常会说明采用的分析口径。两数之和的哈希表解法一般按字典操作的平均 `O(1)` 来分析，得到平均时间复杂度 `O(n)`。

### 判断时间复杂度的步骤

1. 明确输入规模 `n` 是什么。
2. 找出代码中重复执行的部分。
3. 估算循环执行次数。
4. 分析每次循环中的工作量。
5. 检查是否有嵌套循环或额外的线性操作。
6. 合并复杂度，忽略常数因子和低阶项。
7. 说明必要的假设，例如字典操作按平均 `O(1)` 计算。

# 五、空间复杂度怎么判断

## 5.1 什么是空间复杂度？

空间复杂度描述的是：随着输入规模增大，算法运行时所需要的额外空间如何增长。

算法题中通常关注**辅助空间**，也就是算法为了完成计算而额外使用的空间。

题目给定的输入数组本身通常不计入辅助空间，但需要注意题目具体要求的统计口径。

## 5.2 常见空间复杂度

| 复杂度 | 示例 |
|---|---|
| `O(1)` | 只使用固定数量的变量 |
| `O(n)` | 新建一个最多保存 `n` 个元素的字典 |
| `O(n²)` | 新建一个 `n × n` 的矩阵 |

## 5.3 为什么暴力解法是 `O(1)` 辅助空间？

```python
for i, item in enumerate(nums):
    for j in range(i + 1, len(nums)):
        post = nums[j]

        if item + post == target:
            return [i, j]
```

虽然有两层循环，但是只使用了固定数量的变量。

变量数量不会随着 `n` 增长，因此：

\[
\boxed{O(1)}
\]

**注意：嵌套循环不代表空间复杂度一定是 `O(n²)`。**

循环影响的是执行次数，而空间复杂度主要关注额外存储空间。

## 5.4 为什么哈希表解法是 `O(n)` 辅助空间？

```python
cache = {}

for i, item in enumerate(nums):
    cache[item] = i
```

最坏情况下，字典需要保存与输入规模成正比数量的元素。

因此：

\[
\boxed{O(n)}
\]

单次遍历并不会改变这个结论。虽然查找和建表合并到了一个循环中，但字典仍然可能保存 `n` 个不同的数字。

## 5.5 空间复杂度常见误区

### 误区一：循环多，空间就大

不一定。

两层循环如果只使用固定数量的变量，额外空间仍然可以是 `O(1)`。

### 误区二：单次遍历，空间就是 `O(1)`

不一定。

单次遍历的哈希表解法虽然只有一个循环，但字典可能保存 `n` 个元素，因此额外空间是 `O(n)`。

### 误区三：忽略递归调用栈

递归函数会占用调用栈空间。如果递归深度随 `n` 线性增长，调用栈可能需要 `O(n)` 空间。

### 误区四：混淆输入空间和辅助空间

原本就提供的输入数组，通常不算作辅助空间。新建的字典、列表、矩阵等则需要考虑。

# 六、三种解法的对比

设 `n` 为 `nums` 的长度，并按照 Python 字典操作的平均 `O(1)` 来分析。

| 对比项 | Solution1：暴力枚举 | Solution2：两遍哈希表 | Solution3：单遍哈希表 |
|---|---|---|---|
| 主要思路 | 枚举每一对元素 | 先建表，再查找 | 边查找边建表 |
| 时间复杂度 | `O(n²)` | 平均 `O(n)` | 平均 `O(n)` |
| 辅助空间复杂度 | `O(1)` | `O(n)` | `O(n)` |
| 遍历方式 | 嵌套循环 | 两次独立遍历 | 一次遍历 |
| 是否使用哈希表 | 否 | 是 | 是 |
| 自身配对的处理 | 内层从 `i + 1` 开始 | 需要检查索引是否不同 | 先查找、后存入 |
| 主要优点 | 直观、易理解 | 分成两个阶段，逻辑清晰 | 简洁，一次遍历完成 |
| 主要代价 | 大输入下较慢 | 需要额外空间 | 需要额外空间 |

## 优化过程总结

**Solution1 → Solution2**

将反复寻找另一个数字的过程改为哈希表查找，时间复杂度从 `O(n²)` 优化到平均 `O(n)`。

**Solution2 → Solution3**

将“先建表、再查找”合并成一次遍历。渐进时间复杂度仍然是平均 `O(n)`，但代码更简洁，也不必提前保存整个数组的映射。

**最终推荐掌握 Solution3。**

它体现了哈希表题目的经典思路：先检查所需的数据是否已经出现，若没有，再记录当前数据。

# 七、常见误区与注意事项

## 7.1 `in dict` 检查的是键

```python
if other in cache:
    ...
```

它不是检查字典中是否存在某个值，而是检查键 `other` 是否存在。

## 7.2 `cache[other]` 返回的是索引

本题使用：

```python
cache[item] = i
```

所以：

```python
cache[other]
```

返回的是补数对应的索引，而不是补数本身。

## 7.3 为什么单次遍历要先查找再存入？

```python
other = target - item

if other in cache:
    return [i, cache[other]]

cache[item] = i
```

这样可以确保字典只保存之前遍历过的元素，从而避免当前元素与自身配对。

## 7.4 为什么不直接用 `nums.index(item)`？

例如：

```python
nums = [3, 3]

print(nums.index(3))  # 0
```

`list.index(value)` 返回第一个匹配元素的索引。

当数组中有重复数字时，它不一定返回当前遍历位置；而且每次调用还可能需要线性搜索。

既然使用 `enumerate()` 已经拿到了当前索引，就没有必要再调用 `nums.index(item)` 查找。

## 7.5 Python 类型注解

```python
def twoSum(
    self,
    nums: list[int],
    target: int
) -> list[int]:
```

含义：

- `nums: list[int]`：`nums` 预期是一个整数列表。
- `target: int`：`target` 预期是整数。
- `-> list[int]`：函数预期返回整数列表。

类型注解主要用于提高代码可读性、编辑器提示和静态类型检查。普通 Python 运行时通常不会仅仅因为这些注解就自动强制检查参数类型。

# 八、知识总结与自测

## 8.1 今天的核心知识点

1. `enumerate(nums)`：遍历时同时获取索引和值。
2. `for i, item in ...`：利用序列解包将二元组拆成两个变量。
3. `cache[item] = i`：建立数字到索引的映射。
4. `other in cache`：判断补数是否是字典的键。
5. 哈希表：适合快速查找、去重、计数和记录映射关系。
6. 两数之和：利用 `other = target - item` 把配对搜索转化为哈希查找。
7. 两层嵌套循环通常是 `O(n²)`；两个连续的线性循环仍然是 `O(n)`。
8. 固定数量的额外变量通常是 `O(1)` 空间；最多保存 `n` 项的字典通常是 `O(n)` 空间。
9. 单次遍历哈希表解法先查找、后存入，避免当前元素与自身配对。
10. 分析哈希表算法时，通常按字典操作的平均 `O(1)` 进行计算。

## 8.2 自测题

### 问题 1：`enumerate(nums)` 默认从几开始计数？

答案：默认从 `0` 开始。可以通过 `start=1` 等参数改变计数起点，但不会改变列表本身的索引。

### 问题 2：`other in cache` 检查的是键还是值？

答案：检查键。检查值可以使用 `other in cache.values()`。

### 问题 3：为什么暴力枚举通常是 `O(n²)` 时间、`O(1)` 辅助空间？

答案：最坏情况下，两层循环需要检查约 `n(n-1)/2` 对元素，因此时间复杂度为 `O(n²)`。额外只使用固定数量的变量，因此辅助空间复杂度为 `O(1)`。

### 问题 4：为什么单次遍历哈希表解法通常是平均 `O(n)` 时间、`O(n)` 辅助空间？

答案：最多遍历 `n` 个元素，每轮进行常数次平均 `O(1)` 的字典操作，因此平均时间复杂度为 `O(n)`。字典最坏可能保存与 `n` 成正比数量的元素，因此辅助空间复杂度为 `O(n)`。

### 问题 5：为什么单次遍历解法不需要 `i != cache[other]`？

答案：因为每轮先查找补数，找不到时才把当前元素存入字典。查找时，字典中只包含之前遍历过的元素，所以当前元素不会匹配到刚刚存入的自身索引。

### 问题 6：如果有两个连续的 `for` 循环，每个循环都遍历长度为 `n` 的列表，时间复杂度是多少？

答案：

\[
O(n)+O(n)=O(2n)=O(n)
\]

因此是 `O(n)`，而不是 `O(n²)`。

# 推荐记忆模板

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        cache = {}

        for i, item in enumerate(nums):
            other = target - item

            if other in cache:
                return [cache[other], i]

            cache[item] = i

        return []
```

记忆步骤：

1. 创建空字典，保存“数字 → 索引”。
2. 遍历当前数字，计算补数。
3. 如果补数已经出现，直接返回两个索引。
4. 否则记录当前数字及其索引。
5. 如果遍历结束仍没有答案，返回空列表。

> **最重要的不是死记代码，而是理解优化的本质：利用哈希表将反复遍历寻找补数，转化为平均常数时间的键查找。**
