# LeetCode 739：每日温度

## 一、解题思路（约30%）

本题使用**单调递减栈**解决。栈中存储的是温度数组的下标，而不是温度值。栈内下标对应的温度从栈底到栈顶保持递减。

1. 初始化 `Deque<Integer> stack = new ArrayDeque<>()`，用于保存尚未找到更高温度的日期下标；创建长度为 n 的 `answer` 数组，Java 默认将 int 数组元素初始化为 0。
2. 遍历温度数组，使用 i 表示当前日期下标。
3. 当栈不为空，并且当前温度大于栈顶下标对应的温度时，说明找到了栈顶日期的下一个更高温度。使用 `pop()` 弹出栈顶下标，并计算 `answer[stack_top] = i - stack_top`。
4. 处理完所有满足条件的栈顶元素后，将当前下标 i 使用 `push()` 入栈。
5. 遍历结束后，栈中剩余的日期没有更高温度，答案保持默认值 0。

例如 `[73,74,75,71,69,72]`，当温度 72 出现时，可以依次解决 69 和 71 对应日期的问题，计算等待天数。

时间复杂度 O(n)，空间复杂度 O(n)。每个下标最多入栈、出栈一次。

## 二、Java 知识点（约70%）

1. **Deque 与 ArrayDeque**：`Deque<Integer>` 是双端队列接口，`ArrayDeque<>` 是具体实现类。使用接口声明、实现类创建对象，符合面向接口编程的思想。

2. **Deque 模拟栈**：`push(e)` 在队头添加元素，`pop()` 删除并返回队头元素，`peek()` 只查看队头、不删除。三者操作位置一致。注意 `add(e)` 默认在队尾添加，不能与 `push()` 混用，否则会破坏栈的后进先出顺序。

3. **泛型与包装类型**：`Deque<Integer>` 中的 Integer 是 int 的包装类。Java 泛型不支持直接使用基本类型，因此不能写 `Deque<int>`。入栈时自动装箱，取出时可以自动拆箱。

4. **数组初始化**：`new int[n]` 创建指定长度的整数数组，元素默认初始化为 0，因此无需额外遍历初始化 answer。

5. **数组与下标**：`temperatures[i]` 获取当前温度，`temperatures[stack.peek()]` 获取栈顶下标对应的温度。栈存储下标而非温度值，既方便访问原数组，也方便计算日期间隔。

6. **while 与短路运算**：`while (!stack.isEmpty() && ...)` 使用 `&&` 保证先判断栈非空，再访问栈顶，避免空栈操作。while 会持续弹出所有找到更高温度的日期，而不是只处理一个。

7. **边界处理**：循环从 `i = 0` 开始，不需要提前将 0 放入栈中；没有找到更高温度的日期，answer 对应位置自然保持 0。

**核心记忆：单调栈存下标，当前元素解决栈顶元素的问题，最后将当前下标入栈。**

## 补充知识点：Stack 与 Deque

1. **Stack（栈）**：Java 提供的传统栈类，位于 `java.util` 包，继承自 `Vector`，遵循 LIFO（后进先出）原则。常用方法：`push()` 入栈、`pop()` 出栈、`peek()` 查看栈顶、`empty()` 判断是否为空。空栈执行 `pop()` 或 `peek()` 会抛出 `EmptyStackException`。

2. **Deque（双端队列）**：Java 提供的接口，继承自 `Queue`，支持队头和队尾添加、删除及查看元素。使用 `ArrayDeque` 或 `LinkedList` 实现。

3. **相同点**：两者都能实现栈的 LIFO 操作，都支持 `push()`、`pop()`、`peek()`，适用于括号匹配、单调栈、DFS 等算法场景。

4. **不同点**：Stack 是类，继承 Vector，具有同步机制；Deque 是接口，设计更灵活，既能实现栈，也能实现队列。ArrayDeque 通常具有更好的性能，不允许存储 null。

5. **使用建议**：现代 Java 刷题优先使用 `Deque<Integer> stack = new ArrayDeque<>();`，通过 `push()`、`pop()`、`peek()` 实现栈操作，避免使用传统 Stack 类。
