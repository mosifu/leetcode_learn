# LeetCode 142：环形链表 II

## 一、解题思路：快慢指针

采用 Floyd 判圈算法，分为两个阶段：

1. **判断是否有环**：`slow` 每次移动一步，`fast` 每次移动两步。如果两者相遇，说明存在环；如果 `fast == null` 或 `fast.next == null`，说明无环，返回 `null`。
2. **寻找入环节点**：第一次相遇后，将 `slow` 重置到 `head`，`fast` 留在相遇点。两者每次都移动一步，再次相遇的位置就是环的入口。

设头节点到入环点的距离为 \(a\)，入环点到首次相遇点的距离为 \(b\)，环长为 \(L\)。首次相遇时，快指针比慢指针多走的距离是环长的整数倍，因此可得 \(a+b=kL\)。所以从头节点出发走 \(a\) 步，与从相遇点出发走 \(a\) 步，会到达同一个入环节点。

## 二、`Objects.equals()` 与 `==` 的区别

- **`==`**：基本类型比较值；引用类型比较是否指向同一个对象。
- **`Objects.equals(a, b)`**：先处理 `null`，再调用对象的 `equals()` 方法比较。若对象没有重写 `equals()`，通常仍然是比较引用身份；若重写了，则可以比较对象内容。

例如，两个独立创建的 `ListNode` 即使 `val` 相同，`a == b` 通常为 `false`。本题判断的是两个指针是否指向同一个节点，因此推荐使用 `slow == fast`，语义更明确。你的 `Objects.equals(slow, fast)` 在当前 `ListNode` 未重写 `equals()` 的情况下也能正确判断。

## 三、相关 Java 知识

1. **引用赋值**：`slow = head` 只是让 `slow` 指向头节点，不会复制或修改链表。
2. **多变量声明**：`ListNode slow = head, fast = head;` 等价于分别声明并初始化两个引用变量。
3. **短路运算符 `&&`**：先判断 `fast != null`，只有成立才判断 `fast.next != null`，避免空指针异常。
4. **返回引用或 `null`**：`return slow` 返回入环节点的引用；`return null` 表示没有找到环入口。
5. **复杂度**：时间复杂度 \(O(n)\)，额外空间复杂度 \(O(1)\)，且整个过程不修改链表结构。
